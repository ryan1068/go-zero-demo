# 开发流程

本流程把「计划、验证、评审、收尾」变成固定环节，目标是让每次改动都可解释、可验证、可回滚。流程分为 L1/L2/L3 三级，避免小改动背大流程。

## 核心原则

1. **规格先行**：大改没有 spec 和批准的计划，不写代码。
2. **小步变更**：一个提交只做一件事，一步一验证。
3. **验证前移**：重构先写 characterization tests，新功能先写失败测试。
4. **人工把关**：目标、架构、安全、数据迁移、最终验收由人决定。
5. **决策留痕**：spec、ADR、复盘都进仓库，不只留在对话里。
6. **可回滚**：每次变更都要能说清楚怎么退回去。

## 分级

| 级别 | 判断标准 | 走法 |
|---|---|---|
| L1 | 1-3 个文件，改动明确，无接口/数据变化 | 直接改 + 相关测试 + `make check` + commit |
| L2 | 中等改动，涉及多文件但目标明确 | plan mode → 测试 → 分步实现 → 独立 review → `make smoke` |
| L3 | 重构、跨模块、需求模糊、涉及数据迁移 | brainstorming → spec 入仓 → writing-plans → TDD → 分阶段 → review → finish |

## 标准循环

```text
分级 → 澄清 → spec（L3）→ 计划 → 测试先行
→ 小步实现 → 独立 review → 真实验收 → finish
```

### 0. 分级

开始前先说明：**这是 L1/L2/L3**。L1 不需要 spec；L2 至少有一页计划；L3 必须有 spec。

### 1. 澄清

明确：

- 目标
- 非目标
- 约束（兼容性、数据、性能、权限）
- 验收标准

只问会改变实现的问题。业务规则不允许 AI 猜。

### 2. Spec（L3）

用 brainstorming 流程探索，然后把设计写到：

```text
docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md
```

模板见 `docs/superpowers/specs/TEMPLATE.md`。

**停点 1：人批准 spec 后才进入计划。**

### 3. 计划

计划必须满足：

- 拆成 3-5 个可独立验证的步骤
- 每步列出改动文件、测试、验证命令、回滚方式
- 每步不超过一个提交
- 明确「不改什么」

L2 可直接使用 plan mode；L3 用 writing-plans 产出计划文档。

**停点 2：人确认范围和步骤后才开始写代码。**

### 4. 测试先行

- 重构：先写 characterization tests，锁住现有行为
- 新功能：先写失败测试，确认测试能红
- 接口：补契约测试
- 数据层：单测 + 真实 MySQL 集成测试

**停点 3：人确认测试在验证行为，而不是实现细节。**

### 5. 小步实现

每一步：

```bash
make check        # fmt-check + build + test + lint
git add ...
git commit -m "<type>(<scope>): <subject>"
```

**每步停下，等人确认后再继续。**

### 6. 独立 review

使用另一个上下文（人或子 agent）review，不要自己批自己。重点：

- 行为变化
- 错误处理
- 权限与安全
- 数据迁移
- 并发与幂等
- 性能与索引
- 测试是否真的能发现问题

推荐的 review 提示：

```text
独立 review 当前分支相对 main 的 diff，不要修改代码。
重点检查行为变化、错误处理、权限、安全、数据迁移、并发。
按严重程度输出 findings，不要参考我已有的结论。
```

**停点 4：人决定哪些 findings 必须修。**

### 7. 真实验收

```bash
make smoke     # 只读快速检查
make db-backup # 涉及数据变更前备份
```

写操作流程（下单、支付、售后、上传）按 `docs/DEFINITION_OF_DONE.md` 中的清单手工验收，完成后清理测试数据。

**停点 5：人确认真实结果，不只看单测。**

### 8. Finish

- 更新 README / spec / ADR
- 写变更摘要、风险、回滚方式
- 按 Definition of Done 逐项确认
- 开 PR 或合并

## 常用命令

```bash
make check       # 格式检查 + 构建 + 测试 + vet
make gen-check   # 重新生成 API 代码并确认无 diff
make smoke       # 服务启动后的只读冒烟
make db-backup   # 备份三个数据库到 backups/
make test        # 所有模块测试
```

## AI 与人的分工

| 环节 | 人 | AI |
|---|---|---|
| 目标/非目标 | 决定 | 提问、整理 |
| 架构/数据模型 | 批准 | 起草、列取舍 |
| 测试质量 | 抽查 | 编写 |
| 实现 | 定范围 | 执行 |
| Review | 决定修不修 | 找问题 |
| 真实验收 | 最终确认 | 跑脚本、对比数据 |
| 合并 | 决定 | 准备 PR |

## 流程改进

每个 L3 任务结束后做一次简短复盘：

- 哪一步返工最多
- 哪个验证没有提前发现
- 哪条规则需要写进 CLAUDE.md
- 哪些手动步骤应该脚本化

复盘结论更新到本文件或 `CLAUDE.md`。
