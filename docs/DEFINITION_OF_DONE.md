# Definition of Done

每个 L2/L3 变更合并前逐项确认。L1 可只勾选相关项。

## 规格与计划

- [ ] L3 已有 spec，并提交到 `docs/superpowers/specs/`
- [ ] 关键决策已写入 `docs/adr/`
- [ ] 计划中的范围、非目标、回滚方式已确认

## 测试

- [ ] 重构前有 characterization tests，或已有测试覆盖相关行为
- [ ] 新功能有失败测试，且已由红转绿
- [ ] 单测覆盖正常路径、边界、错误路径
- [ ] 涉及数据库的改动有集成测试，或已完成真实环境验证
- [ ] 测试验证行为，不是只断言实现细节

## 质量门禁

- [ ] `make check` 通过（fmt-check / build / test / vet）
- [ ] `make gen-check` 通过（生成代码无漂移）
- [ ] 没有手改 `*_gen.go`、`routes.go`、`types.go`
- [ ] 没有新增 `database/sql` 直连（数据层只能 model + sqlx）

## 安全

- [ ] 没有明文密码、密钥、token 进入仓库
- [ ] 日志中没有密码、token、身份证、手机号等敏感信息
- [ ] 新增接口有鉴权/角色校验
- [ ] 用户输入已校验，SQL 使用参数化
- [ ] 依赖和镜像没有明显高危漏洞

## 验证

- [ ] `make smoke` 通过
- [ ] 写操作流程已在真实环境验证
- [ ] 测试数据已清理，库存/状态已恢复
- [ ] 迁移类改动已备份，并验证过回滚

## 文档与交付

- [ ] README / API 文档 / spec 已更新
- [ ] 变更摘要写清楚：改了什么、为什么、怎么验证
- [ ] 回滚方式已写明
- [ ] 提交信息符合 `<type>(<scope>): <subject>`
- [ ] 独立 review 的 findings 已处理或明确记录

## 已知债务

- [ ] 本次引入的技术债已记录到 spec/ADR 或任务列表
